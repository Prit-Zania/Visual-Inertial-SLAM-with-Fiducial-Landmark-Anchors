# Calibration checklist

1. **Camera identity and image geometry.** Use the same rear camera, stream size, focus policy and stabilization settings for calibration and recording. The app records unrotated camera buffer pixels. Screen orientation is not a camera–IMU extrinsic calibration. Intrinsics must match the recorded image, including crop/scale.
2. **Camera intrinsics.** Run `slam.calibrate camera` using measured chessboard squares and diverse views. Inspect its reprojection RMS and a separate validation recording. A low training RMS alone is insufficient.
3. **IMU units and sample rates.** Accelerometer data must include gravity in m/s²; gyro is rad/s; magnetometer is microtesla. The receiver records all accessible sensor streams, but the estimator selects one sensor per physical measurement type to avoid counting calibrated and virtual copies twice.
4. **Stationary start.** Hold still for at least two seconds. Initialization rejects strongly changing accelerations/angular rates. Constant-velocity motion cannot be distinguished from stationary using IMU alone, so follow the actual stationary-start procedure.
5. **Camera–IMU rotation and timing.** A fixed marker with varied multi-axis rotation can be used with `slam.calibrate rotation-time`. This estimates rotation, gyro bias and a residual offset in ±150 ms. Inspect the residual, repeatability, excitation and solution boundary. A camera whose time base is UNKNOWN may require a larger independently measured clock offset before this refinement is usable. Do not set `camera_clock_offset_verified` simply to bypass an error.
6. **Camera–IMU translation.** Measure it or use Kalibr/full motion calibration. Rotation-only gyro measurements do not determine arbitrary body translations. The example zero lever arm is a placeholder, not a OnePlus measurement.
7. **Accelerometer calibration.** Obtain scale/misalignment and offset from an appropriate multi-orientation calibration and enter `accel_matrix` and `accel_offset`. Initialization only estimates the radial bias in its starting pose.
8. **Noise.** Default process/noise numbers are development values. Tune against stationary logs and validation trajectories. Do not tune only for visually smooth plots; check innovation distributions and covariance coverage.
9. **Compass.** Calibrate hard/soft iron, enter `mag_bias` and `mag_matrix`, and provide `mag_reference_world` in microtesla in the chosen map frame. Set `mag_enabled` only after checking indoor interference. Unreliable accuracy, abnormal field strength or inconsistent updates are rejected.
10. **Depth.** Check the actual `camera_info` report. If Android exposes depth, acquire a measured registration/calibration with `depth_camera_matrix` and `T_camera_depth`. Verify the exact depth image resolution and alignment before setting both range flags. The optional path assumes the supplied depth intrinsics describe that recorded DEPTH16 image. Focus distance is metadata only.
11. **Validation flag.** Set `calibration_verified` only after the measured parameters and independent check are complete. Keep the calibration file with each recording. The processor saves a copy of the configuration used.

The initial phone configuration intentionally remains unverified. Physical calibration cannot be supplied by desktop source code without actual measurements from the device.
